## Цель работы

Собрать основные компоненты встроенной Linux-системы для ARM, подготовить корневую файловую систему на базе BusyBox и проверить загрузку системы с помощью U-Boot в эмуляторе QEMU.

## Состав проекта

В ходе работы подготовлены следующие компоненты:

1. **U-Boot** — загрузчик, собранный для платы Versatile Express с конфигурацией `vexpress_ca9x4_defconfig`.
2. **Ядро Linux 7.2.9** — настроено для ARM с использованием `vexpress_defconfig`. Подготовлены образ ядра `zImage` и файл дерева устройств `.dtb`.
3. **BusyBox** — набор базовых Unix-утилит, собранный со статической линковкой (`CONFIG_STATIC=y`).
4. **RootFS / initramfs** — корневая файловая система на базе BusyBox, упакованная в архив `rootfs.cpio.gz` и образ `uInitrd` для U-Boot.
5. **SD-образ** — виртуальный образ карты памяти, предназначенный для хранения компонентов системы.

## Цепочка загрузки

Последовательность загрузки системы:

**U-Boot → ядро Linux (`zImage`) → initramfs (`uInitrd`) → корневая файловая система BusyBox**

U-Boot загружает ядро, дерево устройств и initramfs в оперативную память, после чего передаёт управление ядру Linux. Ядро использует initramfs в качестве начальной корневой файловой системы и запускает `/sbin/init`.

## Структура репозитория

```text
.
├── u-boot/                 # Исходный код и бинарный файл U-Boot
├── linux-7.2.9/            # Исходный код ядра Linux и собранные файлы
│   ├── arch/arm/boot/zImage
│   └── arch/arm/boot/dts/  # Дерево устройств (точный путь зависит от версии исходников)

├── sd.img                   # Образ виртуальной SD-карты
├── rcS                      # Скрипт начальной настройки файловых систем
└── lab3_report_rejep.pdf    # Итоговый отчёт по лабораторной работе
```

> Фактическое расположение файлов может отличаться в зависимости от того, куда были скопированы результаты сборки.

## Подготовка SD-образа

Создайте пустой образ размером 64 МиБ и отформатируйте его в FAT:

```bash
dd if=/dev/zero of=sd.img bs=1M count=64
mkfs.vfat sd.img
```

Затем скопируйте в корневой каталог FAT-образа файлы, которые будут загружаться из U-Boot: `zImage`, файл `.dtb` для платы Versatile Express и `uInitrd`.

Например, если в вашей системе разрешено монтирование образа через loop-устройство:

```bash
mkdir -p /mnt/sd
sudo mount -o loop sd.img /mnt/sd

sudo cp /путь/к/zImage /mnt/sd/
sudo cp /путь/к/vexpress-v2p-ca9.dtb /mnt/sd/
sudo cp uInitrd /mnt/sd/

sync
sudo umount /mnt/sd
```

Замените пути и имя `.dtb` на фактические пути к файлам в вашем репозитории.

## Запуск QEMU

Запустите эмулятор QEMU с машиной Versatile Express A9, процессором Cortex-A9, 512 МиБ оперативной памяти, U-Boot и SD-образом:

```bash
qemu-system-arm \
  -M vexpress-a9 \
  -cpu cortex-a9 \
  -m 512M \
  -kernel u-boot/u-boot \
  -sd sd.img \
  -serial stdio \
  -display none
```

После запуска должна появиться консоль U-Boot с приглашением `=>`.

## Загрузка системы через U-Boot

В консоли U-Boot выполните команды:

```text
fatload mmc 0 0x60000000 zImage
fatload mmc 0 0x61000000 vexpress-v2p-ca9.dtb
fatload mmc 0 0x62000000 uInitrd

setenv bootargs "console=ttyAMA0 root=/dev/ram0 rdinit=/sbin/init"
bootz 0x60000000 0x62000000 0x61000000
```

Адреса в командах соответствуют следующему расположению компонентов в оперативной памяти:

| Компонент | Адрес |
|---|---:|
| Ядро Linux (`zImage`) | `0x60000000` |
| Дерево устройств (`.dtb`) | `0x61000000` |
| Initramfs (`uInitrd`) | `0x62000000` |

Проверьте, что имя файла дерева устройств в команде `fatload` совпадает с именем файла, записанного на SD-образ. Если команда `fatload` завершается ошибкой, проверьте наличие файла и доступность SD-карты в U-Boot.

## Ожидаемый результат

При успешной загрузке:

- U-Boot находит и загружает ядро, дерево устройств и initramfs;
- ядро Linux запускается на эмулируемой плате Versatile Express A9;
- initramfs становится начальной корневой файловой системой;
- запускается `/sbin/init`, подготовленный в RootFS на базе BusyBox.
